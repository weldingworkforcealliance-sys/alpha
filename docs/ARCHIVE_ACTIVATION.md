## Prepared behavior

- Nightly at 07:17 UTC, from the repository default branch `main`, checking out an explicitly pinned worker commit. No schedule runs from the LTG deployment branch.
- One read-only repeatable-read snapshot of all 25 student-record tables, 25 reviewed course/audit context tables, private certificate artwork and Storage object inventory. Preserves inactive students, all attempts and corrections. Each school gets a separate core-record package; shared context is an archive-administrator-only companion.
- Saved certificate snapshots are rendered to PDF using the preserved code revision and private template. This preserves generated bytes; it does not claim a certificate was previously delivered to a student.
- SSE-S3 encryption, a hold placed on each initial upload, exact-version download/checksum/byte/hold verification, then an independently versioned completion receipt written last. Earlier archives are never removed. The uploader cannot release holds or delete records.
- Every successful run reads the stored receipt and every referenced artifact back again, then verifies all archived rows and file bytes in a temporary isolated PostgreSQL database. This verifies record/file recovery, not restoration of the full LTG application database.
- AWS failure and approximately 30-hour missing-success alarms. Email endpoint is supplied privately when deploying; the owner must confirm the subscription. No student details in alerts or GitHub logs. No GitHub artifact uploads.

## Known limits and cost continuity

A future Storage object causes the worker to fail until an actual-byte resolver is reviewed and installed; it cannot silently produce an incomplete backup. External linked teaching resources are referenced, not downloaded. Account passwords, deployment secrets, payroll tables and email configuration are outside this student archive. This is not a full operational database disaster-recovery solution.

The AWS free-plan end previously displayed March 19, 2027, or earlier credit exhaustion. No paid upgrade is authorized or performed here. Indefinite object retention requires the account to remain funded/active or records to be migrated to independent storage before the free plan ends. The external drive has not been set up. Do not label this permanent production protection until funding/recovery continuity is established.
